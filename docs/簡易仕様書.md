# Handy Markdown Viewer 簡易仕様書

Windows 11 向けの Markdown 閲覧専用アプリ。編集機能は持たない。

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| 名称 | Handy Markdown Viewer（`MarkdownViewer.exe`） |
| 対象 OS | Windows 11（64bit） |
| 形態 | 単体の .exe（インストール不要、約12MB） |
| 実行に必要なもの | Microsoft Edge WebView2 ランタイム（Windows 11 に標準で入っている） |
| 用途 | Markdown ファイルの閲覧。フォルダー内の一覧からの閲覧にも対応 |

## 2. 起動の仕方

| 起動方法 | 動作 |
| --- | --- |
| `MarkdownViewer.exe ファイル.md` | そのファイルを表示。同じフォルダーの Markdown 一覧も左に出す |
| `MarkdownViewer.exe フォルダー` | そのフォルダーの一覧を表示 |
| `MarkdownViewer.exe`（引数なし） | 前回のフォルダー（`last_folder`）と読んでいたファイル（`last_file`）を復元する。前回のフォルダーが無い・見つからないときだけ、フォルダー選択ダイアログを開く |
| `MarkdownViewer.exe --register` | エクスプローラーの「プログラムから開く」と、フォルダーの右クリックのメニューに登録（現在のユーザーのみ） |
| `MarkdownViewer.exe --unregister` | 上記の登録を解除 |

- 対象の拡張子は `.md` `.markdown` `.mdown` `.mkd`。
- フォルダーの右クリック：`HKCU\Software\Classes\Directory\shell\<キー名>`（`%1`）と `Directory\Background\shell\<キー名>`（`%V`、フォルダーの中の何もない場所）に登録する（`shellreg.py`）。キー名はアプリごとに別（`MarkdownViewer`）で、片方がもう片方を上書きしない。解除は、このアプリが書いたキーだけを消す。Windows 11 では、短いメニューには出ず、「その他のオプションを表示」の先の従来のメニューに出る。ドライブそのもの（`Drive\shell`）は対象外。ルート（`F:\`）を `"%V"` で渡されると、引数が `F:"` になるので、起動時に `F:\` へ直す（`shellreg.clean_path_arg`）。
- エクスプローラーからの起動は、上記の登録を行ったうえで、Windows 側で「常に使う」を選ぶ必要がある（Windows 11 の仕様で、既定のアプリはプログラムから切り替えられない）。

### ウィンドウへのドロップ（`filedrop.py`）

- 起動済みのウィンドウに、**Markdown ファイル1つ**、または**フォルダー1つ**をドロップすると開く。ファイルは開いて、そのフォルダーの一覧にする、フォルダーは「フォルダーを開く」と同じ扱い（開いていた文書は閉じる）。
- 次のものは開かず、無視する：Markdown 以外のファイル、2つ以上のドロップ。無視する場合も、既定の動作（ブラウザーでファイルを開こうとする）は必ず止める。
- 実パスは、pywebview がドロップ時にネイティブ側で拾う値（`pywebviewFullPath`）から得る。対象の判定は `filedrop.classify`、画面側の処理は `handleDrop(kind, path)`。
- 印刷ダイアログ・フォント設定などのダイアログが開いている間は、何もしない。
- ドラッグ中に絶え間なく出る `dragover` は、pywebview の DOM イベントでは受けず、画面側の素の JavaScript が既定の動作を止めるだけにしている（Python へ送ると、1回 0.1〜0.3 秒かかって画面が固まり、ドロップが遅れた。実測。確認用スクリプトで固定）。

## 3. 機能

### 3.1 画面構成

- 上部ツールバー（1段）：フォルダーを開く／ファイルを開く／一覧の表示切替／更新／自動更新／検索／フォントの設定。**表示倍率（− 数字の欄 ＋ 100%）・印刷／PDF・HTML は、本文の上端の1行（`#top`。◀ ▶ とパスの右端、`#topbtns`）に置く**（本文に関するものを、本文の側へ。v1.14.0）
- 左：現在のフォルダー、ファイル名の絞り込み欄、件数、ファイル一覧（フォルダーごとの見出し付き）。
- 右：本文。タイトル行に、戻る・進むのボタンと、開いているファイルのパスを表示。
- ライト／ダークは Windows の設定に追従する。
- ウィンドウを狭めたときは、ツールバーをグループ（区切り線で分けた塊）の境目で折り返す。グループの中も、収まらなければ折り返す。ボタンの文字は折り返さない。

### 3.2 ファイル一覧

- 選んだフォルダーの **サブフォルダーを含めて** Markdown を一覧にする（最大5,000件、最大10秒）。
- 読み込みの上限：件数（`MAX_FILES` = 5,000）か時間（`SCAN_SECONDS` = 10秒）の、どちらかに達したら、そこまでの一覧を返し、`truncated` で知らせる（`scan_markdown`）。画面は、件数の行に赤字で「（途中までです）」と出し、途中までの一覧は、ウィンドウを前面に戻したときに自動では読み直さない。
- 次のフォルダーは一覧から除く：`.` で始まるフォルダー、`.git`、`node_modules`、`__pycache__`、`.venv`、`venv`。
- ウィンドウを前面に戻したときに、一覧を自動で取り直す（キャッシュは使わない）。
- **階層表示（アコーディオン）**：相対パス（`/` 区切り）から木を作り（`buildTree(items)`。`items` は `{rel, …}`）、フォルダ行（`.dirrow`：`▸`／`▾`・名前・件数）を押すと開閉する。各階層は、**サブフォルダが先、ファイルが後**（エクスプローラと同じ。サブフォルダは自然順、ファイルは取得した順）。件数は、下の階層を含むファイル数。`renderTreeNode(list, node, depth, leaf)` は、ファイルの行の作り方（`leaf`）を受け取り、通常の一覧・絞り込み・本文検索の結果で共有する。
  - 開閉の状態は、通常の一覧が `tree.open`（フォルダのパス → 真偽。**初めはすべて閉じる**）、絞り込み・本文検索の結果が `tree.sopen`（**初めはすべて開く**。見せ方 `tree.smode` が変わると捨てる）。
  - 開いた文書のあるフォルダは、文書が変わったときに1回だけ開く（`tree.revealed`。描き直しのたびに開くと、自分で閉じられなくなるため）。
  - 状態はフォルダを変えると捨てる（`tree.root`）。一覧の取り直し（`syncList`）では保つ。保存はしない。
  - 絞り込み中も、本文検索の結果も、同じ木で出す（`treeSetup(mode, rels)`）。「すべて開く／閉じる」は「フォルダー」の見出し行（`h2` の右）にあり、いまの見せ方の開閉に効く（`treeMap()`）。サブフォルダが無いときは、ボタンを隠す。「本文を探す」のチェックは、絞り込み欄の上。
  - 試験：`tests/gui_check_tree.py`（21 項目）、`tests/gui_check_bodysearch.py`（本文検索の結果の木）。
- 前回開いたフォルダーと、読んでいたファイルを覚える（`%APPDATA%\MarkdownViewer\settings.json` の `last_folder`、`last_file`）。引数なしで起動すると、これを復元する。
- ファイル名を指定して起動した回は、`last_folder`・`last_file` を更新しない（`Api._persist_location`）。「フォルダーを開く」「ファイルを開く」で利用者が選び直したら、更新を再開する。フォルダー指定の起動は、通常どおり記憶する。
- フォルダー選択ダイアログの開始位置：開いているフォルダー → 前回のフォルダー → 起動したフォルダー。
- 「フォルダーを開く」で別のフォルダーを選ぶと、開いていた文書を閉じて空白の表示に戻す（`Api.close_document`: `last_file` の記録を消し、ウィンドウのタイトルを戻す）。同じフォルダー（大文字小文字・末尾の区切りの違いは同じとみなす）を選んだときは、一覧を取り直すだけで、文書は保つ。

### 3.3 Markdown の表示

| 項目 | 対応 |
| --- | --- |
| 記法 | CommonMark、表（列の配置のコロンも効く）、取り消し線、タスクリスト、見出しへのリンク、文中の URL の自動リンク（GFM の拡張。`autolink.py`）。日本語の文では、括弧などの記号に接した `**強調**` も強調にする（前後が日本語の文字なら空白とみなす。CommonMark の厳密な規則とは異なる。`cjk_emphasis.py`） |
| 埋め込み HTML | 許可したタグだけ表示（表・リスト・画像・`<details>` など）。後述 |
| 図 | Mermaid（` ```mermaid ` のコードブロック）。フローチャート、シーケンス図など Mermaid 11 の図種。Architecture Diagram の追加アイコンは、同梱の iconify `logos`（約2,200個）が使える（`logos:slack-icon` など）。図でそのアイコンが要るときだけ読み込む |
| グラフ | Vega-Lite（` ```vega-lite ` のコードブロック。JSON）。SVG で描く。常に白地（ダークモードでも）。ライブラリは、グラフがあるときだけ読み込む。データは `data.values`（直接記述）、`data.url` の `http(s)` の URL、文書のフォルダー配下の相対パス（`.csv` `.tsv` `.json`、20MB まで）から読める |
| コード | ` ```言語名 ` のコードブロックを色分けする（`highlight.py`。Pygments。約500言語。bat・cmd・batch・dos、powershell・ps1・pwsh、bash・sh・zsh・shell、console のほか、主要言語・設定ファイル・diff など）。言語名は情報行の最初の語（`{.python}` `language-bat` や、`python title="a.py"` も読む）。別名 `cmd` `dos` `jsonc` `patch` `vb` `vba` `gradle` などを補う。**言語名が無い・知らないときは、推測せず色を付けない**。mermaid・vega-lite・vega は触れない（別の部品が読み取る）。復帰文字（`\r`）を含むコードと20万文字超のコードは色を付けない（文字を変えないため）。出力は `<span class="tok-…">`（色だけで、太字・斜体にしない）。色は CSS 変数（`--t-kw` など）で、ライト・ダーク・印刷の3通り。インラインコードは対象外 |
| 数式 | TeX を書き、画面で KaTeX が組む（`vendor/katex/`。0.19.1。MIT）。書き方は、` ```math ` のコードブロック、`$$ ... $$`（独立した行）、文中の `$...$`。Python（`mathtex.py`）が、`<div class="math block">` と `<span class="math inline">` に包む（中の TeX は HTML エスケープする）。画面は、数式があるときだけ KaTeX を読み込んで組む（`Api.get_katex`。フォント（woff2）は data URI にして CSS へ埋め込む。この画面が、ファイルの読み込み元を持たないため）。文中の `$` は、厳しめの規則（markdown-it の dollarmath の `allow_space` と `allow_digits` を切る）。内側が空白で始まる・終わるもの、数字の隣は、数式にしない。閉じていない `$$` は空行で打ち切る。コード（`` ` ``）の範囲をまたいで成立したものは、取り消す（金額の `$` が、あとのコードの中の `$` と組になって、コードを壊したため）。誤りのある TeX は、その位置に、原文と理由を赤で出す（`throwOnError`）。`trust: false`、`output: html`。数式の中の日本語は、`.cjk_fallback` に日本語フォントを指定する（指定が無いと、システムの代替フォントが PDF で Type3 になる）。独立した行の数式は、中央に置き、長いときは横へスクロールする。印刷では、途中で切らない。検索（`vfind.js`）は、数式（`.katex`）の中を対象にしない。 |
| 画像 | ローカルの画像は文書に埋め込んで表示（20MB まで）。書き方は、相対パス（`images/a.png`、`../`）、絶対パス（`C:/…`）、`file:///C:/…`、ドライブを省いた `/Users/…`（文書と同じドライブとみなす）。`file:` は markdown-it の標準では拒まれるため `validate_link` で許している（`javascript:` `vbscript:` と画像以外の `data:` は、従来どおり拒む）。`http(s)` の画像はネットから取得 |
| リンク | `http(s)` / `mailto` は既定のブラウザーで開く。他の Markdown への相対リンクはこのアプリで開く。それ以外のローカルファイル（PDF・Word など。許可した拡張子のみ）へのリンクは、関連づけられたアプリで開く（`Api.open_local`） |
| 文字コード | UTF-8（BOM の有無を問わない）。読めなければ CP932（Shift-JIS） |

### 3.3b 脚注・注釈ブロック・アラート・コードブロックの情報行（`mdext.py`）

ビューアとエディタで同じ内容。Qiita・GitHub への投稿を想定した、広く使われている拡張だけを入れる（独自の記法は作らない）。`make_renderer` が `mdext.apply(md)` を呼ぶ。

| 項目 | 内容 |
| --- | --- |
| 脚注 | `mdit_py_plugins.footnote`。本文の `[^x]` と `[^x]: 説明`。文末に一覧（`<section class="footnotes">`）を出し、本文との間を `#fn1` / `#fnref1` で行き来する（文書内リンクの処理 `scrollIntoView` に乗る）。本文の番号は、括弧なしの数字（`footnote_caption` を差し替え）。**使われない定義は、変換器が捨てる**（Pandoc・GitHub と同じ）。定義のない `[^x]` は文字のまま |
| Qiita の注釈ブロック | `mdit_py_plugins.container`（`name="note"`）。`:::note` に続く語が空・`info`・`warn`・`alert` のときだけ注釈にする（`note_kind`）。ほかの語は注釈にならず、文字は消えない。`<div class="md-note md-note-<種類>">`。見出しは付けない（Qiita の見た目に合わせる）。閉じが無ければ、文書の終わりで閉じる（プラグインの仕様） |
| GitHub のアラート | コアの規則 `github_alerts`（`inline` の後）。`blockquote_open` の次の段落が `[!NOTE]` などだけの行で始まるとき、印を取り除き、英語の見出しの段落（`md-alert-title`）を足す。クラスは `md-alert md-alert-<種類>`。5 種類（NOTE・TIP・IMPORTANT・WARNING・CAUTION）以外・先頭でない印は、ふつうの引用 |
| コードブロックの情報行 | `split_info`: ` ```ruby:app.rb ` → 言語 `ruby`・ファイル名 `app.rb`。` ```diff_ruby ` → `diff`（Pygments の差分の字句解析で、追加・削除に色）。`highlight.language_of` が読み、ファイル名は `filename_html`（`<div class="code-filename">`）が作る。`{.python}` や `python title="a.py"` の書き方には触れない |
| 安全 | 変換器が組み立てる HTML だけ。利用者の HTML は、従来どおり `sanitize.py`（許可タグに `section` を足した）を通る。ファイル名はエスケープする。注釈の種類は、固定の語だけがクラスになる（任意の文字をクラスに入れない） |
| 表示 | `ui.html` の CSS（`#preview`／`#content` の配下。HTML 書き出しは、`collectExportCss` がこの範囲のルールを集める）。色は、半透明の背景と線で、明暗どちらの配色でも読める |
| 変換の失敗 | 変換器が例外を出しても、画面が更新されなくなったり文書が開けなくなったりしないよう、`Api.render`（エディタ）・`Api.open_file`（ビューア）が例外を捕まえて、エラーの文（`mdext.error_html`。例外の文は無害化する）を返す。文中の脚注 `^[...]` が枝番（`subId`）を持たないのに、番号の出力が `meta["subId"]` を読んで `KeyError` になり、プレビューが止まった（v1.22.0 で発生。取り下げ）。この組み合わせは、でたらめな組み合わせの試験（400 通り）で拾う |
| 試験 | `tests/test_mdext.py`（変換 30 項目）、`tests/gui_check_ext.py`（画面。脚注の行き来・色・書き出し） |

### 3.2c 複数のウィンドウ（`multiwin.py`。ビューアとエディタで同じ内容）

複数のウィンドウ（複数のプロセス）で使っても、安全で、使いやすくするための部品。

| 項目 | 内容 |
| --- | --- |
| ずらして開く | 起動のとき、`multiwin.other_windows(WINDOW_MARK)`（`EnumWindows`。タイトルに `Handy Markdown …` を含む、自分以外の、表示中・最小化していないウィンドウ）の左上が、保存した位置に近い（±10px）間、`cascade` で 32px ずつ右下へずらす（最大 12 回）。ずらした先が画面に収まらなければ、ずらさない。最大化の保存があるときは、ずらさない。**位置を保存するとき、開いたときから動かしていなければ、ずらす前の位置を保存する**（`WindowKeeper.offset`。開くたびに右下へ流れないため） |
| 新しいウィンドウ | `multiwin.launch_self(args)`：`sys.executable`（exe 版）、または `sys.executable` ＋ 自分のスクリプトを、`DETACHED_PROCESS` で起動（元のウィンドウを閉じても残る）。`Api.open_in_new_window(path)` は、**Markdown ファイルとフォルダーだけ**を受ける（画面から、任意の実行ファイルを起動させない）。入口は、一覧の Ctrl+クリック・中クリック（`auxclick`）・右クリックのメニュー、リンクの Ctrl+クリック、Ctrl+Shift+N |
| 設定ファイル | `multiwin.write_json_atomic`：一時ファイル（`settings.json.<pid>.tmp`）に書いて `fsync`、`os.replace`。別のプロセスが読んでいて置き換えられないとき（`PermissionError`）は、20ms 待って10回まで試す。書き込みに失敗しても、元のファイルは壊れない。ほかの項目の更新は、書く直前に読み直して項目ごとに上書きする（従来どおり）。同時に書く稀な競合で、先の更新が失われることは、ありうる（表示倍率など、軽い設定だけ） |
| プロセスの生死 | `multiwin.is_alive(pid, created)`：`OpenProcess`＋`GetExitCodeProcess`。**起動した時刻（`GetProcessTimes`）も比べる**ので、pid が別のプロセスに使い回されても取り違えない。調べられないとき（アクセス拒否など）は、動いているものとして扱う（持ち主を、誤って奪わない） |
| 試験 | `tests/test_multiwin.py`、`tests/test_newwindow.py`、`tests/gui_check_newwin.py`（画面 18 項目）。2〜3 個の実際のウィンドウで、ずらして開くこと（32px ずつ）・設定ファイルが壊れないことを確認した |

### 3.2b 戻る・進む（`ui.html` の `nav`）

開いたファイルの履歴。リンクをたどる／一覧から開く／ファイルを開く／ドロップで、`openFile` が成功したとき `navPush` で積む。

| 項目 | 内容 |
| --- | --- |
| 項目 | `{path, top, left}`。離れるとき（`openFile` の冒頭）に、`#scroll` の位置を保存し、戻る・進むで、描き終えたあとに戻す |
| 積まないとき | 同じファイル（直前の項目と同じパス）、自動更新・読み直し（`keepScroll`）、戻る・進むの最中（`nav.busy`） |
| 途中で開く | 現在位置より先（「進む」側）を捨ててから積む。上限100件（古いものから捨てる） |
| 消えたファイル | `openFile` が `'error'` を返したら、その項目を履歴から外す（表示はそのまま） |
| フォルダー | 別のフォルダーのファイルへ移るときは `loadFolder` してから開く。`closeDocument`（フォルダーを変える）で、履歴を空にする |
| 操作 | タイトル行の `#btnBack` `#btnFwd`（押せないときは無効。title に移り先）、Alt+← / Alt+→。ブラウザー既定の動作は止める |
| 試験 | `tests/gui_check_nav.py`（29 項目） |

### 3.2a 自動更新（`ui.html` の `watchTick`、`Api.file_stamp`）

開いているファイルが他のアプリで保存されたら、表示を作り直す。

| 項目 | 内容 |
| --- | --- |
| 検知 | 1秒ごとに `Api.file_stamp`（`os.stat` の更新日時 ns と大きさ）だけを見る。ファイルの中身は、変わったと分かるまで読まない |
| 読む時機 | 目印が変わり、**次の確認でも同じ値**だったとき（書き込みの途中を読まない）。`openFile(path, true)`（読んでいる位置を保つ。数式・図で高さが変わるので、描き終えてからも戻す） |

| 削除・移動 | 表示は残し、1回だけ知らせる。戻ったら、通常どおり更新する |
| 設定 | `auto_reload`（既定は入）。`uiprefs.clean_prefs` が真偽値だけ通す |

### 3.3a 画面の設定と復元（`uiprefs.py`、`Api.get_prefs` / `set_prefs`）

- **フォント**：画面・本文・見出し・コード・図の5部分で、フォント名と大きさ(px)を設定する（ツールバーの「フォント」）。見出しは名前と、H1〜H4 の大きさ(8〜120px。`--h1-size` など。空欄は本文に対する既定の比率)。名前は各部分につき1つだけ（古い設定ファイルにカンマ区切りがあれば、最初の1つを使う）。入力欄は `datalist` の候補つきで、選んだ時点で値を一時的に空欄へ移して候補を全部出す。名前は CSS 変数（`--ui-font` など）に入れる。画面の大きさは、`toolbar`・`side`・`top` の CSS `zoom` で合わせる。図は Mermaid の `fontFamily` / `themeVariables.fontSize` とガントの寸法、Vega-Lite の `config.font` に渡す（変更時に文書を描き直す）。システムのフォント名は、Win32 の `EnumFontFamiliesExW` で取り、入力欄の候補にする（取れなくても直接入力できる）。
- **復元する項目**：フォント、表示倍率、一覧の表示／非表示、自動更新の入切、ウィンドウの位置・大きさ・最大化、使用フォルダーと読んでいたファイル、印刷・PDF の設定。
- **ウィンドウ**：閉じるときに保存する（`WindowKeeper`）。最大化中は、元の位置と大きさ（RestoreBounds）を保存する。起動時、保存した位置がモニターの外に出ているときは、位置を使わず既定の位置で開く。高 DPI で、渡した大きさと読み取る大きさの単位が違う場合に備え、表示後に比を測って補正する。
- **安全**：設定ファイルは手で書き換えられうるので、読み書きとも `uiprefs.clean_*` で型と範囲を確かめ、範囲外はその項目だけ既定に戻す。フォント名からは、CSS を壊す文字（引用符・`;`・`{}`・`<>`・`\`・改行）を取り除く。

### 3.4 表示倍率

- 範囲 10〜500%。`−` `＋` ボタン、数値の直接入力、Ctrl+ホイール、Ctrl+`+` / `−` / `0`（等倍）。
- 「全体表示」（Ctrl+9）は、v1.14.0 でなくした（横にはみ出すときだけ縮め、はみ出さなければ 100% に戻すだけで、使いどころがなかった）。保存済みの設定の `fit` は読み捨てる。
- 本文の幅はウィンドウ幅に追従する（固定幅にしない）。

### 3.5b フォルダー全体の検索（`foldersearch.py`、`ui.html` の `bsearch`。ビューアとエディタで同じ部品）

フォルダーの中の Markdown ファイルの本文を、まとめて探し、一致した行を返す。

| 項目 | 内容 |
| --- | --- |
| 構成 | `foldersearch.search(folder, files, query, case, regex, read, overrides, cancelled)`（画面にも変換器にも依存しない）。ファイルの一覧（`scan_markdown`）と、読み込み（`read_text`）は、呼ぶ側から渡す。`Api.search_folder` が、新しい検索のたびに `_search_id` を進め、前の検索は `cancelled` で、そこで取りやめる |
| 探し方 | 文字列（`re.escape`）か正規表現。**1行ずつ**探し、1行の一致は最初の1件（`count` は一致した行の数）。空の一致（`a*`）は数えない。行は先頭 2,000 文字まで。結果は、一致の前後 40 文字の切り出し（`text`・`s`・`e`）と、元の行の位置（`line`・`col`・`len`） |
| 上限 | 一致 500 行、1ファイル 100 件（返す分。`count` は全部数える）、1ファイル 2MB、10 秒（行 4,000 本ごとにも確認）。超えたら `truncated` ＋ `reason`。読めない・大きいファイルは `skipped` |
| 画面 | 「本文を探す」（`#bodySearch`）・Aa（`#bsCase`）・.*（`#bsRe`）。語の入力から 350ms 後（Enter・オプションの切替では、すぐ）に `runBodySearch`。**`bsearch.seq` で、古い結果が新しい検索を上書きしない**。結果は `renderBodyResults`（ファイル見出し・行・ハイライト・「ほか n 行」。1ファイル 8 行まで表示）。フォルダーが変わったら探し直す（`bsearch.folder`） |
| 行へ移る | `openHit`：ファイルを開き（同じファイルなら、開き直さない）、文書内の検索（`finder`）を同じ語・同じオプションで開く。**本文のブロックに、元の行番号（`data-line`）を付ける**（`make_renderer` の `add_lines`。`sanitize.COMMON` に `data-line` を足した）。一致を順にたどって、各一致が含まれるブロックの行を集め、**探した行を含むブロックの、最初の一致**へ移る（一致が 400 を超えるときは、最初の一致のまま） |
| 試験 | `tests/test_foldersearch.py`（10 件。大文字小文字・正規表現・空の一致・エスケープ・上限・取りやめ・長い行・保存前の内容）、`tests/gui_check_bodysearch.py`（画面の動作 24 項目） |

### 3.6b HTML への書き出し（`ui.html` の `exportHtml`・`buildExportHtml`、`Api.save_html`）

表示している文書を、1つで完結する HTML ファイルにする。**描いた結果をそのまま使う**。

| 項目 | 内容 |
| --- | --- |
| 流れ | `exportHtml`：描画の完了を待つ（`settleRender`）→ Mermaid を明るい配色で描き直す（`printBeforeDiagrams`。印刷と同じ）→ 本文の要素を複製して整える（`buildExportHtml`）→ 元の配色へ戻す → 保存先を選ぶ（`pick_html_path`）→ `save_html` → 完了の画面（警告つき。「ブラウザーで開く」は `open_exported_html`） |
| 描画の完了 | 文書を開く処理（`openFile`）の間は `openBusy` が 0 でない。それが 0 になるまで待つ。念のため、描き終わっていない数式・図・グラフの元の記述が残っていないかも、画面で見る（エラーの枠の中は、待たない）。**`.diagram` の中に `svg` があるかでは、判断しない**（Mermaid が、描画の途中の一時的な空の `<svg>` を、残すことがあり、未完成のものを書き出してしまった） |
| 整形 | 複製の中で、検索のハイライト（`mark.find-hit`）・行番号（`data-line`）・図の元の記述（`data-src`）・図の最小の高さを取り除く。外部リンクに `target="_blank" rel="noopener noreferrer"`。`data:` でも `http` でもない画像は、警告 |
| スタイル | `collectExportCss`：`document.styleSheets` から、**`:root` の規則と、本文の領域（`#content`）の規則だけ**を集め、領域のセレクターを `.md-body` に置き換える（アプリのスタイルを直したら、書き出しにも自動で反映される）。`@media`（暗い配色・印刷用）は含めない＝明るい配色だけ。KaTeX の CSS（`Api.get_katex`。フォントは埋め込み済み）は、数式があるときだけ。ページの基本（余白・幅 960px・印刷用）は、書き出しの側で持つ |
| 含めないもの | スクリプト、外部のファイル（`<link>`・`@import`・外部の `src`）。Vega-Lite は `renderer: 'svg'`、背景 `#ffffff` で描いているので、明るい配色のままで読める |
| 保存 | `Api.save_html`：拡張子 `.html`／`.htm`（無ければ `.html` を足す）、200MB まで、`multiwin.write_text_atomic`（一時ファイル→置き換え。書き込みの途中で止まっても、元のファイルは壊れない）。`open_exported_html` は、**いま書き出したファイルだけ**を開く |
| ビューアの `ask` | ビューアには確認のダイアログが無かったので、エディタと同じ `ask`（`#veil`）を足した（書き出しの完了の画面に使う） |
| 試験 | `tests/test_htmlexport.py`（6 件）、`tests/gui_check_htmlexport.py`（画面 29 項目。実際に書き出して、ファイルの中身と、別のフレームに描いた見た目（背景・見出し・SVG・KaTeX のフォント・表の罫線・画像）を確かめる） |

### 3.6c 発表（スライドショー）（`deck.py`・`deck.js`・`deck.css`・`deck_ui.js`。ビューアとエディタで同じ内容）

| 保存 | HTML スライドショー（役割を `standalone` にして、`save_html` で書く）、スライドの PDF、配布資料の PDF |
| 制限 | 動画・アニメーション・項目ごとの表示なし。図（Mermaid・Vega-Lite）は、明るい配色で描く（`printBeforeDiagrams`）。リンクは開かない。1 回の発表は、1 組のウィンドウ（`DeckHost` が 1 つ） |

## 4. 安全に関する設計

文書は他人から受け取ったものである場合があるため、スクリプトが動かないようにしている。

- **埋め込み HTML は許可リスト方式**（`sanitize.py`）。許可したタグと属性だけを残す。
  - `<script>` `<style>` `<iframe>` `<form>` `<object>` などは中身ごと除去。
  - `on…=` 形式のイベント属性、`javascript:` のリンクは除去。`style` 属性は、改ページの宣言（3.6a）と、表のセル（`th` `td`）の `text-align`（Markdown の列の配置）だけ残してほかは除去。
  - 文字入力欄は表示しない（チェックボックスのみ可）。
- **ローカルファイルへのリンク（`Api.open_local`）は、許可リスト方式**で開く。
  - 書き方：相対パス（文書のフォルダー基準。`../` 可）、`file:///C:/…`、`C:/…`。`sanitize.py` の `LINK_SCHEMES` に `file` を加え、開いてよいかは Python 側で判断する。
  - 拒否：UNC・`file://サーバー/…`（ネットワーク共有への接続による情報の漏えいを避けるため）、存在しないファイル、`OPEN_EXTENSIONS`（`.pdf` `.doc(x)` `.xls(x)` `.ppt(x)` `.rtf` `.odt` `.ods` `.odp` `.txt` `.csv` `.tsv` と画像）以外。`.exe` `.bat` `.lnk` `.docm` `.xlsm` などは開かない。シンボリックリンクは、リンク先の実体でも同じ拡張子の検査をする。
  - 開く操作は、リンクをクリックしたときだけ（`os.startfile`）。
- **Mermaid は `securityLevel: strict`** で動かす。図の中のスクリプトやクリック動作は無効。
- Mermaid 本体は exe に同梱しており、図の描画にネット接続は要らない。
- **Vega-Lite のデータ読み込み（`data.url`）は経路を限定**する。
  - `http(s)` の URL：ネットから取得する（画像の `http(s)` と同じ扱い）。
  - 相対パス：Python 側（`Api.read_data`）で検査して読む。基準は、いま開いている文書のフォルダー（画面側から渡された値は使わない）。そのフォルダーとその下だけ。絶対パス、ドライブ指定、UNC、`file:`、`../` での外出、シンボリックリンクで外へ出るもの、`.csv` `.tsv` `.json` 以外、20MB 超は拒否する。
  - それ以外のスキームは拒否する。
- Vega-Lite 本体も exe に同梱しており、グラフの描画自体にネット接続は要らない（`http(s)` のデータを使う場合を除く）。
- 文書を書き換える機能はない（閲覧専用）。

## 6. 制限事項

- ウィンドウへのドロップで開けるのは、Markdown ファイル1つかフォルダー1つだけ（それ以外は無視する）。本物のエクスプローラーからのドロップは、利用者の実機で確認済み（ファイル・フォルダーとも開く。反応の遅れも解消した）。
- 閲覧専用。編集、置換はない。文書内の検索はあるが、図（SVG）の中の文字は対象外。
- URL の自動リンクは、`http://` `https://` `www.` で始まるものだけ（メールアドレスや `example.com` のような裸のドメインは対象外）。URL に使うのは ASCII の文字だけで、日本語を含むパスは日本語の手前までのリンクになる（日本語の文に埋め込まれた URL が、後ろの日本語まで巻き込まないため。実装は `autolink.py`）。
- 図（Mermaid）・グラフ（Vega-Lite）の文字には、指定のフォントの後ろに日本語の字形を持つフォント（游ゴシック UI、メイリオ）を必ず足す（`ui.html` の `DIAGRAM_JP_FONTS`）。指定のフォントに日本語の字形が無い（既定の Trebuchet MS など）と、ブラウザーがシステムの代替フォントを使い、PDF に Type3 フォントとして埋め込まれて、Acrobat Reader が「埋め込みフォント T3Font_n を抽出できません」と警告した。
- 本文も同じ理由で、**印刷・PDF のときだけ**、絵文字を色のない文字として描く（`font-variant-emoji: text`。カラー絵文字は Type3 になる）。また、本文のフォントに字形が無い記号（`▦` など）の代替フォントも Type3 になるため、本文のフォントの後ろ（総称名 `sans-serif` の前）に、埋め込めるフォント（メイリオ、MS ゴシック）を足す（`@media print`）。画面の表示は変えない（カラー絵文字のまま）。総称名は、後ろにフォントを並べても先に確定して後ろへ進まないため、既定の `--body-font` から外して使う側で最後に付けた。
- PDF の構造（Type3 の個数）で確かめた（図の全種類、取扱説明書、文書に出る全記号。印刷の確認用スクリプトで固定）。Acrobat Reader そのものでの表示は確かめていない。
- 日本語の斜体（`*…*`）は、本文のフォントが日本語の字形を傾けられないと（メイリオ系。斜体の字形は持つが、日本語は傾けない）、日本語の部分が斜めにならない（英字は斜めになる）。メイリオ系では斜めにならず、既定の「游ゴシック UI」や BIZ UD ゴシックでは斜めになる（canvas で描いて通常との差を見る実測。原因は、斜体の字形を持つフォントではブラウザーが擬似的に傾けないためと考えられる）。代わりの字形に切り替える対応はしない（斜体の部分だけ字体が変わるため）。
- 埋め込み HTML の `style` 属性による見た目の指定は効かない（`align` `border` など HTML の属性と、改ページの指定、表のセルの配置は効く）。
- 数式は、KaTeX が対応する範囲（LaTeX の全機能ではない。`\usepackage` のような、文書全体にかかわる命令は使えない）。検索は、数式の中を対象にしない。
- 相対リンクで、このアプリの中で開けるのは Markdown ファイルのみ。PDF・Word などは、許可した拡張子に限り、関連づけられた別のアプリで開く。それ以外の種類は開かない。
- リンク先のファイルを開く許可リストは、`mdviewer.py` の `OPEN_EXTENSIONS` に固定している（設定では変えられない）。
- 非常に大きな文書や、図の多い文書での性能は検証していない。
- Mermaid の図は、本文中の最終的な置き場所で描く（ガントチャートが親要素の幅で全体の幅を決めるため。画面外で描くと本文幅より広く作られ、縮小されて文字が小さくなる）。
- Vega-Lite は式の評価に `new Function` を使う（`<script>` を動かさない方針とは性質が異なる）。厳密に揃えるなら `vega-interpreter` の追加が必要。
- Vega-Lite の `http(s)` のデータは、相手のサーバーが CORS を許可していないと読めない。
- Vega-Lite のグラフは常に白地で、ダークモードの配色には切り替わらない。印刷時の描き直しの対象外。
- 署名のない exe のため、初回起動時に Windows の SmartScreen が警告を出すことがある。
- 登録（`--register`）は、書き込む内容を、テスト用の別のキーで確かめた（本物の登録を書き換えないため）。実際のエクスプローラーでの、フォルダーの右クリックから開く動作は、利用者の実機で確認済み（Windows 11 では「その他のオプションを表示」の中に出る）。ファイルのダブルクリックでの起動（関連づけ、既定のアプリにする）も、利用者の実機で確認済み。
- 印刷では、両面印刷・給紙トレイ・用紙の種類など、プリンター固有の設定は指定できない。
- 印刷・PDF 出力は、自動検証（用紙サイズ、ページ数、ページ範囲、ダイアログの動作）を通しているが、実際の紙への印刷は、仮想プリンター（Microsoft Print to PDF）の受け付けまでしか検証していない。
- Architecture Diagram の追加アイコンは `logos` 集のみ。それ以外のアイコン集（`mdi:` など）は同梱しておらず、「?」の印で表示される。
